# 09 — Test strategy

## 1. Existing tooling reused

- `cargo xtask ci`: fmt, clippy `-D warnings`, workspace tests, assets, layers, WASM.
- `crates/engine/src/tests.rs::hostile_params_never_panic`: every command with absurd parameters (keep it green for the future `vcs.*` commands).
- `cargo xtask corpus [--download]`: the upstream's existing document corpus.
- `cargo xtask visual-diff`: visual comparison of renderings.
- Per-format round-trip tests in `crates/formats/src/tests.rs`.

## 2. Document corpus

To be assembled in a folder outside the repository (files produced by Word must not be committed — *clean room* rule); only **synthetic** documents generated by code enter the repository.

| Case | Source |
|---|---|
| Simple document | generated (`sample::sample_document`) |
| 100 pages | generated (controlled repetition) |
| Many images (PNG, JPEG, EMF, TIFF) | generated |
| Simple, merged, nested and layout tables | generated |
| Multi-level lists | generated |
| Table of contents, notes, internal/external links | generated |
| Word 97-2003 `.doc` | `xtask corpus` corpus |
| Recent real-world DOCX | the owner's documents (outside the repository) |
| Non-representable items (colours, WordArt, sections, headers) | generated |

## 3. Preservation tests (§16.2)

Implemented in this branch:

| Test | Checks |
|---|---|
| `formats::tests::native_markdown_is_html_free_and_stable` | zero HTML; images in `assets/`; `export ∘ import ∘ export` identical over 3 cycles |
| `formats::tests::native_markdown_assets_are_content_named` | image name = content, deduplication, no state leak between imports |
| `formats::tests::native_markdown_reports_adaptations` | `<br>` and `<a id>` removed and reported |
| `formats::tests::html_lines_finds_tags_but_not_comments_code_or_autolinks` | the HTML detector itself |
| `engine::tests::docx_to_native_markdown_round_trip` | full milestone: DOCX → `.md` + `assets/` → reopen → identical re-save → edit by command → reopen → PDF |

To add:

1. **Property** (`proptest`): for every generated document, `export_native(import_with(export_native(d))) == export_native(d)` and `html_lines == []`.
2. **No-silent-loss invariant**: all visible text of the original document is found in the `.md`, except what the `Report` counts (comparison of normalised text).
3. **Syntax / semantics separation**: compare two `.md` files by their `Flow` (structure, text, links, images) rather than byte for byte, to tell purely syntactic differences from real losses.
4. Full corpus as a scheduled job (not on every commit): aggregated report of adaptations per document.

## 4. Security tests

- Images: `..` paths, absolute paths, URLs, symlinks, huge files, thousands of references (`LocalImages` limits + `MAX_IMAGE_REFS`).
- Hostile Markdown: deep nesting, unclosed brackets (existing parser budgets), unclosed HTML comments.
- Malformed or gigantic forge responses (`forge` crate, phase 5).

## 5. Git / forge tests (phases 4-5)

- `LocalGitStore`: temporary repositories created by the test; history, restore, version with images.
- `ForgeStore`: simulated HTTP transport (JSON responses recorded from the public documentation), no network call in `cargo test`.
- Conflict scenarios: two sessions edit the same paragraph / different paragraphs.
- Real integration tests, manual or scheduled, against a test repository on each forge (never with the owner's credentials in the repository).

## 6. Performance

Measurements (added to `cargo xtask stats` or a dedicated bench): opening and saving the `.md` of a 100-page document, typing latency, PDF export time, native and WASM.

## 7. Usability (§16.3)

Scenarios run by users who know neither Markdown nor Git, timed and compared with Word: open a DOCX, change a heading, insert an image, edit a table, save, close/reopen, export to PDF, save a version, go back to a previous version, read a colleague's comments. The same journeys are automated through the control channel (`docs/control-protocol.md`) and `ui_shot` screenshots without stealing focus.
